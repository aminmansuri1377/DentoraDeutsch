# اتصال و seed — نسخهٔ 0.2.2

این نسخه قطع اتصال سرور را علت‌یابی قطعی نمی‌کند. برای قطعی‌های موقت، seed بازیابی محدود دارد و ابزار تشخیص دقیق‌تر شده است.

## نصب اصلاح

سرور را متوقف کنید. فایل‌های نسخه جدید را جایگزین کنید، اما .env، .env.local و certs/supabase-ca.crt شخصی خودتان را حفظ کنید. گواهی CA و رمز دیتابیس داخل بسته نیستند.

تنظیمات فعلی که آزمون SSL را پاس کردند حفظ شوند. DATABASE_SSL_CA_FILE باید ./certs/supabase-ca.crt باشد. CLIهای seed و check اکنون مانند Next فایل‌های .env.local و .env را می‌خوانند؛ اگر مقادیر متفاوتی در این فایل‌ها دارید هماهنگ کنید. متغیرهای موجود PowerShell بر فایل‌ها اولویت دارند.

به‌ترتیب و جداگانه اجرا کنید:

```powershell
npm install
npm run db:generate
npm run db:seed
```

قطع موقت اتصال با SEED_RECONNECT مشخص می‌شود. seed فقط همان upsert ناموفق را با PrismaClient و pool جدید تکرار می‌کند. برای هر مرحله حداکثر 3 تکرار با تأخیرهای 1، 2 و 4 ثانیه و در کل حداکثر 12 تکرار وجود دارد. خطاهای SSL، رمز و schema خودکار تکرار نمی‌شوند. این سیاست مخصوص seed است: تمام نوشته‌های آن upsert با کلید یکتا و update خالی هستند. عملیات مالی یا امتیازدهی برنامه به این روش تکرار نمی‌شوند.

پس از Seed complete:

```powershell
npm run db:check
npm run dev
```

check ده تراکنش فقط‌خواندنی pg و ده تراکنش Prisma را اجرا می‌کند. موفقیت آن تضمین پایداری دائمی شبکه یا موفقیت همه عملیات نوشتن نیست. در صورت شکست، مرحله، زمان UTC و نوع خطا نمایش داده می‌شود، بدون چاپ رمز یا URL کامل. از خروجی برای تطبیق با لاگ‌های Postgres/Pooler استفاده کنید.

TCP keepalive در اتصال مشترک فعال شده است. این تنظیم مانع restart سرور، timeout سمت سرویس یا قطع شبکه نمی‌شود.

## migration قبلی

این بسته migration جدید ندارد و تاریخچه migration را خودکار دستکاری نمی‌کند. وضعیت failed اولیه مستقل از seed است. با توجه به نتیجه قبلی No difference detected، پس از اطمینان از توقف سایر migrationها:

```powershell
npx prisma migrate resolve --applied 202610280001_initial
npx prisma migrate status
```

اگر قفل advisory همچنان نگه داشته شده است باید اتصال نگه‌دارنده بررسی شود؛ reset نکنید و قفل را خاموش نکنید.

## محدودیت اعتبارسنجی

آزمون بازیابی شامل شبیه‌سازی قطع پس از ثبت داده و اجرای مجدد کل seed بدون رکورد تکراری است. اتصال واقعی به Supabase کاربر در محیط توسعه این بسته در دسترس نبوده است. قطع مکرر پس از تمام تلاش‌ها نیازمند لاگ سرور یا بررسی مسیر شبکه است؛ موفقیت seed به‌تنهایی به معنای رفع علت قطع اتصال نیست.
