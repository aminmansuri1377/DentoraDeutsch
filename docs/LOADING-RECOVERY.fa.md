# رفع خطای ورود به /lernen و کندی توسعه — نسخهٔ آذر ۱۴۰۵

این اصلاحیه جایگزین رفتار SSR معرفی‌شده در `LOADING-PERFORMANCE.md` است.

## چرا صفحهٔ خطا نمایش داده می‌شد؟

بعد از اصلاح قبلی، در `/lernen` کوئری دیتابیس پیش از نمایش صفحه روی سرور
اجرا می‌شد. خطای اتصال یا timeout در این کوئری باعث رفتن کل مسیر به
`src/app/error.tsx` می‌شد. `reset()` لزوماً اتصال یا Server Component را دوباره
بارگذاری نمی‌کرد.

- اکنون Layout همچنان احراز هویت می‌کند، اما بارگذاری کاتالوگ داخل Client Query
  مستقل انجام می‌شود. خطای آن فقط در همان بخش نشان داده می‌شود؛ دکمهٔ
  «Erneut versuchen» همان درخواست را دوباره می‌فرستد.
- دکمهٔ خطای عمومی «Seite neu laden» یک Refresh واقعی انجام می‌دهد.
- SQL کاتالوگ و وضعیت تکمیل درس‌ها به دو کوئری موازی با نتیجهٔ شخصی‌سازی‌شده
  تقسیم شده‌اند؛ محتوای کاربر در Cache سراسری ذخیره نمی‌شود.
- درخواست GET بعد از ۲۵ ثانیه در مرورگر با پیام قابل‌تکرار خاتمه می‌یابد.
  درخواست‌های نوشتنی/mutation هرگز با تایمر کلاینت قطع نمی‌شوند.
- `pg` timeout خواندن ۲۰ ثانیه دارد؛ این تنظیم اتصال خراب را تعمیر نمی‌کند.
- برای کاهش درخواست اضافه، Refetch هنگام Focus از React Query غیرفعال شده است.
- `npm run dev` از Turbopack پیش‌فرض Next.js 16 استفاده می‌کند؛ برای بازگشت
  به Webpack، `npm run dev -- --webpack` یا `DENTORA_DEV_WEBPACK=true`.
- در حالت PGlite محلی، seed نمونه بعد از یک اجرای موفق دیگر در هر Restart تکرار
  نمی‌شود. تغییر دیتابیس راه دور ایجاد نشده است.

## تشخیص تأخیر واقعی Supabase

۱. سرور را متوقف کنید. `npm run db:check` اتصال فعلی .env را چک می‌کند.
۲. متغیر `DENTORA_PERF_LOG=true` را در `.env.local` یا Vercel تنظیم کنید.
۳. زمان `learning.catalog` و `api.trpc` در Terminal/Logs را با زمان Network مقایسه کنید.
۴. برای مقایسهٔ *فقط سرعت توسعه*، `npm run dev:local` را اجرا کنید. این
   دستور از دیتابیس جداگانهٔ PGlite با محتوای آزمایشی استفاده می‌کند و هیچ
   دادهٔ واقعی Supabase را بارگذاری نمی‌کند.
۵. برای اندازه‌گیری سرعت Production، از `npm run build` سپس `npm run start`
   و Network بدون Fast Refresh استفاده کنید. اولین بازدید dev شامل زمان
   کامپایل هم هست و با تولید یکسان نیست.

اگر همچنان `PG_*`، `P1001`، `P1017` یا `ETIMEDOUT` می‌بینید، علت اتصال
دیتابیس/شبکه را از لاگ‌های ترمینال و Supabase بررسی کنید. تغییر UI یا
React Query این قطعی‌ها را درمان نمی‌کند. لاگ‌ها حاوی محتوای درخواست یا
اطلاعات اتصال نیستند.
