# پروفایل و Community

این patch روی نسخه‌ای اعمال می‌شود که patch مسیرهای یادگیری و خرگوش روی آن نصب شده است.

```powershell
git apply --check .\DentoraDeutsch-profile-community.patch
git apply .\DentoraDeutsch-profile-community.patch
npm install
```

## راه‌اندازی عکس‌ها (یک بار)

عکس‌ها در **Supabase Storage** ذخیره می‌شوند، نه در فایل‌سیستم موقت Vercel.
از همان پروژهٔ Supabase، مقدار Project URL و کلید **service_role** را بردارید.
کلید service_role رمز دیتابیس و کلید anon نیست. آن را فقط در محیط سرور نگه دارید؛
در پیام، Git یا متغیرهای `NEXT_PUBLIC_` قرار ندهید.

به فایل واقعی `.env` و Environment Variables در Vercel اضافه کنید:

```dotenv
SUPABASE_URL="https://YOUR_PROJECT_REF.supabase.co"
SUPABASE_SERVICE_ROLE_KEY="YOUR_SERVICE_ROLE_KEY"
SUPABASE_MEDIA_BUCKET="dentora-media"
```

سپس در ریشه پروژه اجرا کنید:

```powershell
npm run storage:setup
npm run dev
```

دستور setup فقط در صورت نبودن bucket، یک bucket خصوصی می‌سازد. برای bucket موجود
عمداً دسترسی‌ها را تغییر نمی‌دهد. راه جایگزین: در Supabase → Storage یک bucket
**Private** با نام دقیق `dentora-media` بسازید. اجازهٔ عمومی upload یا policy باز
لازم نیست: درخواست‌ها ابتدا با نشست NextAuth در سرور برنامه بررسی می‌شوند.

پس از افزودن envها در Vercel، تغییرات را push و Redeploy کنید. برای این patch
migration جدید و اجرای seed لازم نیست؛ User.image و Media از قبل در schema هستند.

## تغییرات

- آپلود/تغییر عکس از خود پروفایل و تنظیمات؛ نمایش در پروفایل، پست و کامنت.
- پروفایل با اطلاعات دانشگاه، bio، XP، استریک، تعداد پست‌ها و ارتباط‌ها، مدال‌ها.
- نمایش دنبال‌کننده‌ها/دنبال‌شونده‌ها با صفحه‌بندی و لینک پروفایل.
- وضعیت واقعی دنبال‌کردن از دیتابیس، دنبال‌کردن و لغو دنبال‌کردن.
- سه تب جدیدترین، پست‌های من و ذخیره‌شده‌ها، جست‌وجو و بارگذاری پست‌های بیشتر.
- پست متن و/یا یک عکس، لایک، ذخیره و لغو آن‌ها، کامنت با صفحه‌بندی و حذف پست خود.
- نویسنده‌های بدون username نیز با شناسه به صفحهٔ پروفایل متصل می‌شوند.
- متن‌های ریز خواناتر؛ خروج با نوشتهٔ قرمز در پایین پروفایل.
- تغییرات با mutation و بازخوانی cache اعمال می‌شوند؛ reload دستی لازم نیست.

## عکس‌ها و دسترسی

فقط JPG/PNG/WebP تا ۲ مگابایت و ۱۶ مگاپیکسل. فایل روی سرور واقعاً decode و به WebP
تبدیل می‌شود، اطلاعات EXIF حذف می‌شود؛ SVG و انیمیشن پذیرفته نمی‌شوند.
عکس‌های پست به حداکثر ۱۴۴۰ پیکسل و عکس پروفایل به ۳۸۴ پیکسل تبدیل می‌شوند.
آپلود محدود به کاربر واردشده و origin مجاز است. کلید Storage هرگز به مرورگر نمی‌رود.
تصاویر از مسیر هم‌دامنهٔ `/api/media/:id` با کنترل دسترسی ارائه می‌شوند.
عکس فعلی پروفایل و عکس پست منتشرشده برای اعضای واردشده دیده می‌شوند؛ عکس آپلودشدهٔ
بدون پست فقط برای صاحب آن قابل مشاهده است. خصوصی‌بودن پروفایل جزئیات صفحهٔ پروفایل
را پنهان می‌کند، ولی پستی که کاربر در Community منتشر کرده عمومیِ اعضای برنامه است.

عکس‌های قبلی/آپلودهای استفاده‌نشده ممکن است در Storage باقی بمانند؛ برای نصب بزرگ‌تر
یک سیاست پاک‌سازی دوره‌ای برای Media بدون مصرف در نظر بگیرید. فایل‌های کاربران دیگر
و تصویرِ متصل به پست را نباید به عنوان فایل بدون مصرف حذف کرد.

## بررسی انجام‌شده

تست‌های دیتابیس موقت برای فالو/آنفالو، شمارنده‌ها، ذخیره‌ها، کامنت‌ها، صفحه‌بندی،
پروفایل خصوصی و مالکیت تصاویر؛ تست تبدیل و محدودیت تصویر؛ TypeScript و build.
دسترسی زنده به Storage و envهای Vercel شما در این محیط وجود ندارد؛ پس از setup، یک
عکس آزمایشی در پروفایل و یک پست تصویری ثبت کنید و با حساب دوم آن‌ها را بررسی کنید.
